# RAG-помічник по навчальних матеріалах

Відповідає на питання **лише за вашими файлами** (PDF, DOCX, MD, TXT) і показує джерело: файл і фрагмент (для PDF ще й сторінку).
Пошук працює локально (BM25), відповідь формує локальна модель через Ollama. Усе безкоштовно, без ключів, файли не залишають комп'ютер.

## Швидкий старт

Потрібні Python 3.10+ та [Ollama](https://ollama.com/download).

```bash
# 1. Модель (один раз). 8 ГБ RAM: gemma3:4b або llama3.2:3b; 16 ГБ RAM: qwen2.5:7b або llama3.1:8b
ollama pull gemma3:4b

# 2. Залежності
cd solution
python -m venv .venv
.venv\Scripts\activate          # Windows;  macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

# 3. Налаштування (за замовчуванням уже працює з Ollama)
copy .env.example .env          # macOS/Linux: cp .env.example .env

# 4. Свої матеріали покладіть у solution/docs/ 
python index.py                 # побудувати індекс

# 5. Запуск
streamlit run app.py            # веб-чат у браузері
# або з командного рядка:
python ask.py "Що таке 3НФ?"
```

Ollama має бути запущена (застосунок у треї або `ollama serve`). Якщо її немає, програма не падає, а переходить у режим «лише пошук» і показує найрелевантніші фрагменти.

## Приклад запуску

У `docs/` лежать мої навчальні матеріали з предмета «Теорія інформації та кодування» (DOCX). Після `python index.py` можна спробувати:

```bash
python ask.py "Коли ентропія дорівнює нулю?" --no-llm     # без моделі, працює завжди
python ask.py "Коли ентропія дорівнює нулю?"              # з Ollama
```

## Вимірювання якості (цифри для звіту)

1. Складіть `eval/questions.json` з ~20 питань по своїх матеріалах (формат — у `eval/questions.sample.json`):
   `q` — питання, `source` — файл з відповіддю, `keywords` — корені слів, які мають бути у правильній відповіді.
2. Запустіть:

```bash
python eval.py --questions eval/questions.json            # з моделлю
python eval.py --questions eval/questions.json --no-llm   # лише пошук
```

Результат виводиться таблицею й зберігається в `eval/results.json` (скопіюйте його в `../evidence/`).

## Журнал використання

Кожне питання автоматично записується в `../evidence/usage_log.jsonl` (час, питання, джерела, час відповіді, токени).
Кнопки 👍/👎 у веб-чаті додають у журнал оцінку відповіді. Це доказ реального використання.

## Тести

```bash
python -m unittest discover -s tests -v
```

Тести працюють без мережі й без моделі (Ollama підмінена).

## Структура

```
solution/
├── app.py            # веб-чат (Streamlit)
├── ask.py            # питання з командного рядка
├── index.py          # побудова індексу
├── eval.py           # вимірювання якості на наборі питань
├── rag/
│   ├── loader.py     # читання PDF/DOCX/MD/TXT, нарізання на фрагменти
│   ├── bm25.py       # пошук BM25 по символьних триграмах
│   ├── llm.py        # Ollama (за замовчуванням) або Claude API
│   ├── pipeline.py   # питання -> пошук -> відповідь -> журнал, fallback
│   └── config.py     # налаштування з .env
├── docs/             # ваші матеріали
├── eval/             # набори питань
└── tests/
```

## Налаштування (`.env`)

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | `ollama` (локально) або `claude` |
| `OLLAMA_MODEL` | `gemma3:4b` | модель Ollama |
| `OLLAMA_NUM_CTX` | `8192` | вікно контексту (мале значення обрізає фрагменти) |
| `TOP_K` | `5` | скільки фрагментів передавати моделі |
| `MIN_COVERAGE` | `0.3` | поріг відсікання питань не по темі (0 — вимкнути) |

Необов'язково: `LLM_PROVIDER=claude`, `pip install anthropic`, `ANTHROPIC_API_KEY=...`.

## Обмеження

- Скановані PDF без текстового шару не читаються (потрібен OCR).
- BM25 шукає за збігом слів, тому синонім без спільних коренів може не знайтися. Тоді переформулюйте питання.
- Таблиці та формули з PDF витягуються як звичайний текст і можуть втратити структуру.
- Якість відповіді залежить від моделі: малі моделі інколи плутають деталі, тому завжди звіряйтеся з показаним джерелом.
- Після додавання файлів потрібно переіндексувати (`python index.py` або кнопка в боковій панелі).
